# АННОТАЦИЯ

В настоящем документе приведено описание программной системы EmployeeMonitor System, предназначенной для сбора, хранения, анализа и визуализации метрик производительности сотрудников. Система обеспечивает автоматическую генерацию правил контроля, уведомления по отклонениям и формирование отчётов. Архитектура построена с применением семантического моделирования организационной структуры. Документ оформлен в соответствии с требованиями ЕСПД (ГОСТ 19.402-78, ГОСТ 19.105-78).

## 1. Общие сведения

**1.1 Обозначение и наименование программы**

Наименование программы — **EmployeeMonitor System**

**1.2 Программное обеспечение, необходимое для функционирования программы**

Система реализована по микросервисной архитектуре и функционирует в следующем окружении:
- Серверная часть (Java + Spring Boot) — REST API и бизнес-логика.
- Модуль сбора данных (Python + Flask) — получение метрик из внешних систем.
- Клиентская часть — веб-интерфейс для администраторов, руководителей и аналитиков.
- СУБД PostgreSQL — основное хранилище метрик и сущностей.
- OWL-онтология — модель организационной структуры.
- Telegram Bot API — оповещения и взаимодействие с пользователями.

**1.3 Языки программирования**
- Java — серверная логика.
- Python — сбор данных и интеграция с внешними API.
- JavaScript — интерфейс пользователя и Telegram-бот.
- OWL (RDF/XML) — модель структуры организации.

## 2. Функциональное назначение

Программа предназначена для:
- автоматизированного сбора и хранения данных о производительности сотрудников;
- генерации пользовательских и онтологически обусловленных правил контроля;
- оповещения через мессенджеры при выявлении отклонений;
- построения отчётов и аналитических сводок;
- интеграции с системами контроля задач (GitLab), учёта времени (Kimai), мессенджерами (Telegram), системой распознавания лиц.

## 3. Описание логической структуры

**3.1 Архитектура программы**

Система состоит из следующих компонентов:

1. **Backend-сервер (Spring Boot)** — основная бизнес-логика и REST API.
2. **Модуль сбора данных (Flask)** — интеграция с GitLab, Kimai, Telegram, камера распознавания лиц.
3. **PostgreSQL** — база данных, хранящая сущности: сотрудники, метрики, правила.
4. **OWL-модель** — семантическое описание структуры организации.
5. **Модуль правил** — автоматическая проверка условий и генерация событий.
6.  **Модуль уведомлений** — рассылка сообщений через Telegram и Email.
7.  **Модуль отчётов** — генерация PDF, Excel и визуализация через Grafana.

**3.2 Структура программы**
- OWL-модель описывает структуру организации: отделы, роли, метрики.
- Backend извлекает правила из OWL и применяет их к метрикам.
- При срабатывании правил формируются уведомления.
- Модуль отчётов агрегирует данные по отделам и периодам и отправляет результаты пользователям.

## 4. Используемые технические средства

- ОС: Windows/Linux для серверной части; любая ОС с браузером для клиента.
- ПО: Java 17+, Python 3.10+, PostgreSQL, Spring Boot, Flask, Telegram Bot API, Protégé, OWL API.
- IDE: IntelliJ IDEA, VSCode.
- Библиотеки: Apache POI, JasperReports, Chart.js, OWL API, SPARQL.

## 5. Вызов и загрузка

- Серверная часть запускается через java -jar employeemonitor.jar.
- Flask-модуль запускается командой python app.py.
- Telegram-бот активируется при запуске Spring Boot.
- Веб-интерфейс доступен по адресу http://localhost:8080.
- OWL-модель загружается вручную или автоматически из файла ontology.owl.

## 6. Входные данные

- Расписание и список метрик из OWL-модели.
- Данные от внешних сервисов:
    - GitLab (коммиты, Merge Requests);
    - Kimai (отработанное время);
    - Telegram (активность в чатах);
    - система распознавания лиц (время прихода/ухода).
- SQL-правила и конфигурации уведомлений.

## 7. Выходные данные

- Уведомления в Telegram и Email о нарушениях (например, низкая активность).
- Ежедневные/недельные/месячные отчёты (Excel, PDF).
- BI-дашборды (через Grafana или Power BI).
- Агрегированная статистика по отделам и ролям.
- Журнал событий: список срабатываний правил, нарушений и предупреждений.

**АННОТАЦИЯ**

В данном документе приведено руководство пользователя по работе с системой **EmployeeMonitor System**, реализующей автоматизированный сбор, анализ и визуализацию метрик производительности сотрудников с применением методов семантического моделирования. Оформление документа «Руководство оператора» произведено по требованиям ЕСПД (ГОСТ 19.505-79, ГОСТ 19.105-78).

## 1. Назначение программы

**1.1 Функциональное назначение программы**

Программа предназначена для мониторинга производительности сотрудников. Она осуществляет сбор метрик из различных источников (GitLab, Kimai, Telegram, система распознавания лиц), генерирует уведомления по заданным правилам и формирует отчёты.

**1.2 Эксплуатационное назначение программы**

Программный продукт ориентирован на руководителей, HR- специалистов, аналитиков и системных администраторов. Позволяет оперативно выявлять нарушения и оценивать эффективность работы сотрудников.

**1.3 Состав функций**

1.  Сбор метрик из внешних систем
2.  Отслеживание активности сотрудников
3.  Генерация правил на основе онтологии
4.  Отправка уведомлений в Telegram и Email
5.  Формирование отчётов (PDF, Excel)
6.  Отображение данных в веб-интерфейсе

## 2. Условия выполнения программы

**2.1. Минимальный состав аппаратных и программных средств**
- Серверная часть запускается на компьютерах с ОС Windows или Linux.
- Для взаимодействия с системой оператор использует:
    - современный веб-браузер (доступ к административной панели);
    - Telegram-клиент (для получения уведомлений и работы с ботом).

**2.2 Требования к оператору**

В зависимости от выполняемых задач под оператором понимается:
- **Технический специалист**, обеспечивающий запуск и обслуживание компонентов системы (должен владеть базовыми знаниями Linux/Windows, уметь запускать backend, работать с OWL-файлами и базами данных).
- **Администратор**, управляющий структурой организации, правилами контроля, расписанием формирования отчётов (должен разбираться в метриках и уметь пользоваться интерфейсом веб-приложения).
- **Руководитель подразделения**, просматривающий отчёты и получающий уведомления (достаточно базовых навыков работы с браузером и Telegram).

## 3. Выполнение программы

**3.1 Загрузка и запуск программы**
- Запуск серверной части осуществляется через java -jar employeemonitor.jar
- Flask-модуль запускается командой python app.py
- Telegram-бот активируется вместе с сервером
- Веб-интерфейс доступен по адресу: http://localhost:8080
- OWL-модель загружается через интерфейс или автоматически из файла ontology.owl

**3.2 Выполнение программы**

После запуска системы пользователю доступны следующие функции через веб-интерфейс или Telegram-бота:
1.  Настройка и редактирование правил контроля на основе OWL- модели;
2.  Просмотр текущих метрик сотрудников и отделов;
3.  Просмотр журналов нарушений;
4.  Формирование и получение отчётов за выбранный период (день, неделя, месяц);
5.  Получение уведомлений в Telegram и Email при нарушении установленных правил;
6.  Управление расписанием автоматической проверки условий.

**3.3 Завершение программы**

Завершение работы производится посредством остановки сервисов (сервер, бот, модуль сбора). Web-интерфейс закрывается в браузере.

## 4. Сообщения оператору

Оператор взаимодействует с системой через веб-интерфейс и Telegram- бота. Все уведомления формируются в рамках заданных правил и приходят в Telegram. В случае внутренних ошибок технические сообщения отображаются в системной консоли или логах, предназначенных для технического специалиста.

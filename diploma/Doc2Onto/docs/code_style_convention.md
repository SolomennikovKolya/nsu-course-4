# Конвенция UI-кода Doc2Onto

Этот документ фиксирует правила оформления UI-модулей в `ui/`. Цель — единообразие
и предсказуемая навигация по любому виджету. Форматирование и часть линт-правил
автоматизированы через `ruff` (см. `pyproject.toml`).

## 1. Структура файла

Каждый файл с UI-кодом начинается так:

```python
"""Краткое описание модуля одной строкой."""

from __future__ import annotations

# stdlib
from pathlib import Path
from typing import Optional

# сторонние
from PySide6.QtCore import Qt, Signal
from PySide6.QtWidgets import QWidget, QVBoxLayout

# локальные
from app.context import get_theme_manager
from models.document import Document
```

Правила:

- **Module docstring обязателен.** Одна строка, в настоящем времени, описывает *что
  это за модуль*, а не как им пользоваться.
- **`from __future__ import annotations` обязателен.** Аннотации трактуются как
  строки: можно писать `Document | None` без import-цикла, ускоряется импорт.
- **Порядок и группировка импортов** делает ruff (`I` rules). Руками не править.
- **Никаких `# region` / ASCII-баннеров между импортами.**

## 2. Структура класса-виджета

Порядок секций внутри класса фиксирован:

```python
class FooWidget(QWidget):
    """Однострочное описание виджета."""

    # 1. Сигналы (class attributes)
    something_changed = Signal(object)

    # 2. __init__
    def __init__(self, parent: Optional[QWidget] = None):
        super().__init__(parent)
        self._build_ui()
        self._wire_signals()

    # 3. Публичные методы (set_*, get_*, refresh_*, apply_theme и т.д.)
    def set_document(self, doc: Optional[Document]): ...

    # 4. Слоты — _on_*
    def _on_selection_changed(self): ...
    def _on_theme_changed(self, _theme_id: str): ...

    # 5. Внутренние хелперы — _build_*, _refresh, _select_* и т.п.
    def _build_ui(self): ...
    def _wire_signals(self): ...
```

- **Без комментариев-разделителей** внутри класса (`# ---------- public API ----------`).
  Порядок методов сам по себе является структурой; IDE сворачивает методы.
- **`__init__` не должен быть длинной простынёй.** Если построение UI занимает
  больше ~15 строк — вынести в `_build_ui()` (или `_build_left_panel()` +
  `_build_right_panel()` для составных виджетов). Подписки на сигналы — в
  `_wire_signals()`.
- **Слоты называются `_on_<событие>`**: `_on_doc_upload`, `_on_theme_changed`.
- **Билдеры частей UI называются `_build_<что>`** и возвращают `QWidget` либо
  устанавливают поля `self._*` и возвращают `None` (одно из двух — выбрать и
  держаться единого варианта в файле).

## 3. Имена и видимость

- Приватные поля и методы — с одним подчёркиванием: `self._tree`, `self._on_*`.
- Двойное подчёркивание (`__`) не использовать — оно ломает наследование без выгоды.
- Константы модуля — `UPPER_SNAKE_CASE`, в начале файла после импортов.
- Енумы и «псевдо-енумы» (классы с константами-строками) — внутри того модуля, где
  используются, если они не общие.

## 4. Сигналы и события

### Локальные сигналы (виджет → родитель)

Используются для конкретных UI-событий в дочернем виджете: `document_selection_changed`,
`document_deleted`, `committed`. Объявляются как class attribute, подписываются в
`_wire_signals` родителя.

### Шина доменных событий (`app.events.AppEvents`)

Для **глобальных** событий, на которые реагирует несколько несвязанных частей
интерфейса: `templates_changed`, `ontology_changed`, `document_status_changed`.
Виджет подписывается в `__init__` напрямую на шину, родитель ничего не «прокидывает».

Правило отнесения:
- интересно **только** родителю → локальный сигнал;
- интересно ≥ 2 несвязанным частям UI → шина.

Сигнал шины посылается **после** того, как доменное состояние обновлено: подписчики
читают актуальное состояние из менеджеров, не передают через сигнал «как обновиться».
Это снимает зависимость от порядка вызова подписчиков.

## 5. Темы

- Каждый виджет, которому нужна реакция на смену темы, в `__init__` подписывается:
  `get_theme_manager().theme_changed.connect(self._on_theme_changed)`.
- Метод-обработчик называется ровно `_on_theme_changed(self, _theme_id: str)`.
- Цветовые токены и стили читаются из `get_theme_manager().current.*`, никаких
  хардкод-цветов в коде виджетов.
- Метод `apply_theme()` на родительских виджетах остаётся только пока не все
  потомки подписались на шину тем; в идеале он исчезает.

## 6. Строки UI

- Сообщения в `QMessageBox`, заголовки диалогов, плейсхолдеры — допустимы inline,
  если используются один раз.
- Если строка повторяется в нескольких местах или потенциально пойдёт в локализацию
  — выносить в константу модуля или в `ui/strings.py`.

## 7. Комментарии

- Комментарии описывают **«почему»**, а не «что». Имена методов и переменных
  должны делать «что» очевидным.
- Docstring у класса — одна строка с назначением. Многострочный docstring —
  только если есть нетривиальный контракт.
- Не оставлять закомментированный код. Удалять — git помнит всё.

## 8. Автоматизация

- `ruff check .` — линтер.
- `ruff format .` — форматирование (заменяет autopep8/black).
- В VS Code: расширение `charliermarsh.ruff`, format on save, fix on save.
- Перед коммитом ожидается чистый `ruff check`. Pre-commit hook опционален, но
  рекомендуется.
